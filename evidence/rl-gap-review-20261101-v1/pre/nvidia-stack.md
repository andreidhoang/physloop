# NVIDIA executable RL path audit

Agent-authored research review for P-031, 2026-11-01. This supports the S2 prerequisites and proposed S4/G9 focus; it is not a training result, Huy's mastery evidence, a scientific prediction, or execution authority. DOC_AUTHORITY, START, the protected-file manifest and P-031 were read. Only public source/text was inspected. No environment installation, asset download, license acceptance, rental or training occurred.

The practical starting path is Alpamayo 1.5 continuous-action-expert RL with the VLM frozen, using AlpaGym. The current open-loop reasoning recipe is a different optimizer path. The strongest newly verified risks are a mismatch between online training rewards and processed evaluation metrics, warning-only staleness handling in the Gym trainer, and retry/drop behavior that can change which scenes supply training data.

**Concrete correction to P-031's unresolved collision aggregation:** for this exact Gym dependency, the aggregation is now source-verified. A capped front-or-lateral episode predicate can be formed as min(C_front + C_lateral, 1) because both inputs are boolean MAX aggregates. Merely adding two −10 terms can produce −20. The current reward configuration supports linear metric terms and distance_to_gt, not this cap. The derived offline collision_at_fault metric is not produced by the online raw scorer map. A capped alternative requires a qualified new term/scorer or explicit adapter change; it is not automatically a configuration-only experiment.

**Concrete correction to parity admission:** setting allowed_outdated_steps=0 is useful configuration but insufficient evidence. Log and assert the actual rollout weight version, trainer version and original/replayed log density. Reject mismatches for the parity check. A passing first-step check also does not qualify later asynchronous updates.

**Additional source-derived risk:** online reward aggregation can include warm-up events and later incident consequences that the processed evaluator excludes. This is a potential mismatch, not an observed error rate. A known-answer fixture with a warm-up-only collision, then a separate post-first-incident event, should demonstrate the two paths' exact outputs before choosing the learning target.

## Hardware, reasoning recipe and model claims

The [Gym onboarding hardware section](https://github.com/NVlabs/alpagym/blob/972d160eed0e23d388497851504a3a233fec5879/docs/ONBOARDING.md#L22) recommends two GPUs with at least 40 GB each, 100–150 GB base disk and approximately 1.5 GB per NuRec scene. Its local-run section reports testing on two RTX 6000 Ada GPUs. These are documented configurations, not a mathematical memory lower bound. The same guide requires an NCCL P2P check and describes a slower shared-memory fallback. One GPU is discussed for smaller models. The existing PhysLoop single-GPU synthetic host check establishes neither the two-GPU training topology nor 10B training fit on a 96 GB card.

The [open-loop recipe README](https://github.com/NVlabs/alpamayo-recipes/blob/2e907dab31e5353f42b2c8a2f79d7e39b6e0d42c/recipes/alpamayo1_x_rl/README.md#L36) documents at least five 80 GB GPUs: four policy GPUs and one rollout GPU. Its FAQ says this path trains the VLM's text/discrete trajectory tokens, not the continuous expert. Twelve completions are configured in the [local TOML](https://github.com/NVlabs/alpamayo-recipes/blob/2e907dab31e5353f42b2c8a2f79d7e39b6e0d42c/recipes/alpamayo1_x_rl/toml/alpamayo_rvla_rl_local_test.toml#L52). The joint-reward example uses Lingo-Judge. These are not prerequisites for the two-GPU continuous-expert study, and a reasoning-checkpoint export does not automatically provide a trained continuous expert.

NVIDIA's [closed-loop tutorial](https://developer.nvidia.com/blog/how-to-post-train-autonomous-vehicle-models-in-closed-loop-with-nvidia-alpamayo/) supplies a setup/export walkthrough, not a measured PhysLoop success guarantee. Its broad single-GPU scaling language should not override its concrete two-GPU 10B example.

The [August 4 Super article](https://developer.nvidia.com/blog/generate-trajectories-reasoning-traces-and-auto-labels-with-nvidia-alpamayo-2-super/), introductory model-description paragraph, confirms a combined model described as RL-post-trained. The [Super card](https://huggingface.co/nvidia/Alpamayo2-Super), Architecture and Inference sections, describes the backbone/expert split and an H100 inference profile. Neither inspected description supplies the final component-by-component RL schedule, reward weights, judge or complete training recipe. Inference memory is not training memory. No Super replacement or joint reasoning/expert study follows from these sources.

## What this review establishes

Source inspection establishes the dependency graph, shipped optimizer target, implemented reductions, configuration values and control-flow risks. Algebra establishes that one-candidate centered advantage is zero and that averaging log densities changes the ratio. This review did not execute even a synthetic training test, so it establishes no actual gradient, weight-sync, numerical-parity, runtime-memory, learning or behavioral result.

Before renting, public-source CPU fixtures can test reward formulas, aggregation differences, masks, group standardization, likelihood-reduction known answers, missing-data rejection and version-admission logic. Such fixtures should exercise pinned implementation pieces and an independent oracle; replacing CUDA internals with a reimplementation is not upstream runtime proof.

The newly rented GPU phase is needed for model loading/conversion, full parameter/gradient audits, NCCL behavior, replay parity, export parity, realistic memory/throughput/cost, and a complete simulated update. A replicated held-out study is then needed to establish reward-to-behavior transfer. Passing installation or one update is not that result.

The proposed RL-first thesis remains technically plausible: study whether continuous-expert optimization changes held-out behavior, identify which reward/credit/exploration/protocol mechanism explains failures, and test one correction. The source evidence favors reproducing and auditing the expert path before expanding into simultaneous reasoning training, Super, reactive traffic or distributed scaling. Impact and novelty remain research questions for the broader paper review.
