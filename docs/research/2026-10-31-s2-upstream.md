## Reviewed JSON output contract

Authoritative writer: [challenge processing.py, lines 269–374](https://github.com/NVlabs/alpasim/blob/e121e59141dc391f6c295513d6dadc840a419149/src/eval/src/eval/aggregation/processing.py#L269-L374).

File: `aggregate/results-summary.json`.

Top level:

- `schema_version: 1`
- `scene_score_enabled: boolean`
- `rollouts: array` — use these per-rollout records for pairing.
- `metrics_results: array` — aggregated run diagnostics; not independent paired observations.
- `score_criteria: object` when score is enabled; optional `telemetry`.

Minimal illustrative scored row, invented only to show shape (not a measured result):

```json
{
  "run_uuid": "run-a",
  "run_name": "policy-a",
  "clipgt_id": "clipgt-example",
  "rollout_id": "rollout-example",
  "metrics": {
    "run_uuid": "run-a",
    "run_name": "policy-a",
    "clipgt_id": "clipgt-example",
    "rollout_id": "rollout-example",
    "progress_clipped_rel": 0.8,
    "gt_dist_traveled_m": 20.0,
    "collision_at_fault": 0.0,
    "offroad": 0.0,
    "left_corridor_laterally": 0.0
  },
  "status": "pass",
  "passed": true,
  "score": 1.0,
  "failure_reason": null,
  "score_metrics": {
    "progress_clipped_rel": 0.8,
    "progress_rel": 0.8,
    "progress_score": 1.0,
    "collision_at_fault": 0.0,
    "offroad": 0.0,
    "dist_to_gt_trajectory": 0.2,
    "lateral_dist_to_gt_trajectory": 0.2,
    "left_corridor_laterally": 0.0,
    "gt_dist_traveled_m": 20.0
  }
}
```

The actual value key is **`score`**, not `scene_score`. `metrics` contains the time-aggregated source metric columns and repeats the run/clip/rollout identity; only internal `trajectory_uid` and `rollout_uid` are removed. The writer obtains identity fields with `row.get` and does not validate their types. `create_metrics_dataframe` declares identity strings, but an importing adapter should reject missing/non-string/empty identifiers instead of coercing them. `run_name` is human-readable and is not the unique run key.

Status is `pass` or `fail`; `passed` is boolean. Disabled scoring produces `status="unscored"` with null `passed`, `score`, `failure_reason` and `score_metrics`. [JSON sanitization](https://github.com/NVlabs/alpasim/blob/e121e59141dc391f6c295513d6dadc840a419149/src/eval/src/eval/aggregation/processing.py#L258-L266) turns nonfinite floating values into null. Null does not mean zero.

### Score semantics

[scene_score.py](https://github.com/NVlabs/alpasim/blob/e121e59141dc391f6c295513d6dadc840a419149/src/eval/src/eval/aggregation/scene_score.py) requires finite `progress_clipped_rel`, `gt_dist_traveled_m`, `collision_at_fault`, `offroad` and `left_corridor_laterally`.

With [default configuration](https://github.com/NVlabs/alpasim/blob/e121e59141dc391f6c295513d6dadc840a419149/src/eval/src/eval/schema.py#L161-L175), progress score is min(clamp(progress_clipped_rel,0,1)/0.8,1), except a GT distance below 5 m receives progress score 1. Any nonzero at-fault collision, offroad or lateral corridor exit sets score 0; the first applicable failure reason follows that order. Otherwise score equals progress score.

Consequences for an adapter:

- Score is continuous in [0,1] and higher is better.
- A poor-progress rollout can have score 0 with `passed=true`. Do not derive a binary failure from score or a score from status.
- Preserve raw `status`, `passed`, `failure_reason` and metrics as provenance.
- The same `schema_version=1` is used on [main](https://github.com/NVlabs/alpasim/blob/affc2eab209fa43bdfa2f26c0f8d437922d78a68/src/eval/src/eval/aggregation/processing.py#L290-L364), where lateral-corridor summary fields are absent. Version 1 alone does not establish protocol compatibility.

### Infrastructure failures are also zero scores

[failed_rollouts.py](https://github.com/NVlabs/alpasim/blob/e121e59141dc391f6c295513d6dadc840a419149/src/eval/src/eval/aggregation/failed_rollouts.py#L12-L84) emits:

- `status="fail"`, `passed=false`, `score=0.0` when scoring is enabled;
- `failure_reason` from `error` or fallback `failure_reason`;
- `metrics` containing run/clip/rollout identity plus an **`error` key**, whose value can itself be null;
- all `score_metrics` null except `progress_score=0.0`;
- a missing/falsey rollout ID replaced by `failed-{index}`.

Test for presence of `metrics.error`, not only its truthiness. These rows must be quarantined as incomplete infrastructure evidence; they are not completed driving outcomes. The challenge presets explicitly enable aggregation with failed rollouts. Expected-schedule matching is needed to detect missing rows as well.

## Per-timestep records and identity gaps

[The writer](https://github.com/NVlabs/alpasim/blob/e121e59141dc391f6c295513d6dadc840a419149/src/eval/src/eval/data.py#L2027-L2077) establishes the actual long-format parquet columns:

`name, timestamps_us, values, valid, time_aggregation, clipgt_id, rollout_id, run_uuid, run_name`.

The code uses `name` and `values`. The `metric_name` / `value` spellings in the aggregation function's docstring are stale. [Collection](https://github.com/NVlabs/alpasim/blob/e121e59141dc391f6c295513d6dadc840a419149/src/eval/src/eval/aggregation/main.py#L40-L67) reads `rollouts/<scene_id>/<rollout_uuid>/metrics.parquet`; the [tutorial](https://github.com/NVlabs/alpasim/blob/e121e59141dc391f6c295513d6dadc840a419149/docs/TUTORIAL.md#L139-L162) documents `_complete` and resolved configuration outputs.

The summary does not guarantee road identity, stratum, a cross-policy replicate match, requested/actual step counts, a full-trajectory deviation maximum, the sampling design or a complete planned schedule. [Internal `rollout_uid`](https://github.com/NVlabs/alpasim/blob/e121e59141dc391f6c295513d6dadc840a419149/src/eval/src/eval/aggregation/processing.py#L102-L141) is a dense rank derived from run/rollout identity, not proof of matched seeds or replicates.

Offline adapter preparation should therefore require externally supplied, exact-key sidecars:

1. Identity map: `run_uuid, clipgt_id, rollout_id, policy, scene_id, road_id, stratum, replicate_id`.
2. Completion/deviation evidence: requested and actual steps, independently validated completion, and a declared full-trajectory maximum deviation convention.
3. Expected schedule with the full planned identities; duplicates, missing, unexpected or incomplete rows block comparison.
4. A pinned evaluator/protocol identity, resolved config and source hashes.

These are proposed plumbing admission requirements, not a substitute for Huy's S2 sampling design or physical validity definition.

### Truncation and absent-map caveats

[Default aggregation modifiers](https://github.com/NVlabs/alpasim/blob/e121e59141dc391f6c295513d6dadc840a419149/src/eval/src/eval/aggregation/processing.py#L37-L64) remove pre-evaluation timestamps and truncate after the first collision/offroad event. [The aggregation entry point](https://github.com/NVlabs/alpasim/blob/e121e59141dc391f6c295513d6dadc840a419149/src/eval/src/eval/aggregation/main.py#L155-L168) also truncates after ordinary `dist_to_gt_trajectory >= configured threshold`. [The filter](https://github.com/NVlabs/alpasim/blob/e121e59141dc391f6c295513d6dadc840a419149/src/eval/src/eval/aggregation/modifiers.py#L72-L104) retains the triggering timestep.

Thus summary deviation can be a maximum only over retained timestamps. It does not prove a maximum over the complete simulated rollout, especially after an earlier collision. Keep full-rollout validity evidence separate; do not silently discard ≥4 m records.

[Aggregation also inserts `offroad=0.0`](https://github.com/NVlabs/alpasim/blob/e121e59141dc391f6c295513d6dadc840a419149/src/eval/src/eval/aggregation/processing.py#L750-L759) when the offroad column is absent because no map is loaded. Source metric/map completeness must be verified before a real score is admitted; the summary's zero alone cannot prove offroad was measured.

## Scorer fix and exact boundary

[The pinned scorer](https://github.com/NVlabs/alpasim/blob/e121e59141dc391f6c295513d6dadc840a419149/src/eval/src/eval/scorers/ground_truth.py#L11-L47) searches backwards for at least 1 m of GT displacement to determine the endpoint direction. If a forward endpoint ray exists, lateral distance is the minimum of trajectory distance and perpendicular distance to that ray for points ahead of the endpoint. This prevents tiny stationary-tail segments from defining the final direction. [Corridor exit](https://github.com/NVlabs/alpasim/blob/e121e59141dc391f6c295513d6dadc840a419149/src/eval/src/eval/scorers/ground_truth.py#L174-L217) uses `>= corridor_m`, with maximum time aggregation. Ordinary trajectory deviation and lateral corridor deviation are different quantities.

[#198's source-only minimal reproduction](https://github.com/NVlabs/alpasim/issues/198) supplies geometries for a future pinned known-answer test; no dataset is needed. It has not been executed in this audit. Import signature at this pin is `_lateral_distance_to_gt(gt_linestring, point, end_direction)`; historical reproductions include an additional length argument and must not be copied unchanged.
